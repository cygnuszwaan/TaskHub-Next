# Backend modules and tests

One entry per file in `functions/`, what it holds and the contracts that matter, then how the code is tested.

## Modules

- `functions/index.js` (endpoints and engine)
- `functions/calendar.js` (event listing, cleanup and busy-window helpers)
- `functions/auth.js` (owner check for the HTTP endpoints)
- `functions/breaks.js` (pure: `lunchWindows`, the lunch break as one busy window per local day, and `padWindows`, windows widened by the gap, which the engine applies to every calendar event)
- `functions/planner.js` (pure: `planSchedule`, the deterministic scheduler described in scheduling-engine.md, and `sortByUrgency`; its optional `grouping {radiusKm, maxDeferDays}` with `locations` (task id to coordinates) and `anchors` ([{date, latitude, longitude}]) is the area preference described in step 5 of the scheduling engine, and changes nothing when absent)
- `functions/geo.js` (pure: `coordsOf`, a usable `{latitude, longitude}` or null, `distanceKm`, the haversine distance in km, and `sameArea`, within a radius)
- `functions/schedule.js` (pure: validation and repair of the planner's slots including project order (`checkProjectOrder`), the gap check between slots, `buildFixedSlots` for the project members a run must respect without placing them, `buildAnchors` for the slots a run leaves in place that count as holding their day for the area preference, and `matchLockedEvents`)
- `functions/tasks.js` (pure merge of model changes and engine results into the task list, `moveToQueueNumber`, `manualTaskChange`, the new-task change built from a manual entry, `needsTagFill`, `cleanTags` and `newTaskIds`)
- `functions/batch.js` (pure: `applyBatch`, one batch action (`MOVE_TO_TOP`, `SET_PROJECT`, `SET_DUE`, `SNOOZE`) applied to the named tasks, `moveToTop` (the selected tasks first in their queue order, ranks renumbered 1..n) and `needsReschedule`, the page's `snoozeNeedsReschedule` rule)
- `functions/description.js` (pure: `normalizeDescription`, validation of a task's description text; `readDescription`, the description in a client's fields: `description`, else an older page's non-empty `comments` text, so an older page's empty box can never erase a description)
- `functions/invoice.js` (pure: the job sheet's invoice figures in whole cents: `entryFigures` (labour = the sheet's time to the minute, else the estimate, at the rate; materials = the sum of costed items; travel = the km, kept as tenths so sums are exact, at the travel rate, only with both), `travelTenths`, `travelText`, `sumFigures`, `isInvoice`, `figuresText`, `formatMoney` as NZD)
- `functions/money.js` (pure: `normalizeMoney`, `normalizeHourlyRate`, `normalizeTravelRate`, `normalizeMaterialCost`: amounts in dollars as numbers or plain decimal text, rounded to cents)
- `functions/travel.js` (pure: `normalizeTravelKm`, validation of a task's travel distance)
- `functions/contact.js` (pure: `normalizePhone` (one line, at most 40 characters) and `normalizeEmail` (at most 100, address-shaped), each null for none and undefined for an unusable value)
- `functions/backup.js` (pure apart from injected clients: `runBackup`, backup names and retention)
- `functions/alerts.js` (pure: `weatherMoves`, `weatherMoveMessage`, `runFailedMessage`, `reminderWindow` (the stretch since the last reminder check, at most 30 minutes back), `dueReminders` (timed, not yet started, no running timer, whose start less the lead falls in the window, earliest first) and `reminderMessage`, with the local date and time text helpers)
- `functions/push.js` (pure apart from the injected messaging client: `normalizePushToken`, `normalizePushTokens`, `addPushToken` and `removePushTokens` (the device list, at most `MAX_PUSH_TOKENS` 5), `buildMessage`, `testPayload`, `summarizeSend` (sent, failed, the dead tokens and the error codes), `sendToTokens` (one message per token through `messaging.sendEach`), `isDeadTokenCode` (not registered or invalid token only) and `publicSettings`, settings with the tokens replaced by a `pushDevices` count)
- `functions/shopping.js` (pure: the Miscellaneous list, `normalizeShoppingText` (1..`MAX_SHOPPING_TEXT` 100 characters, whitespace collapsed), `normalizeShoppingItems`, `addShoppingItem` (at most `MAX_SHOPPING_ITEMS` 100; an item already there, ignoring case, is not added twice) and `removeShoppingItem`)
- `functions/materials.js` (pure: `normalizeMaterials` (validation of a materials list, costs included), `hasOpenMaterials` and `heldTaskIds`, the tasks the engine must not schedule)
- `functions/timer.js` (pure: time tracking on a task: `isRunning`, `elapsedSeconds`, `startTimer`, `pauseTimer`, `abortTimer`, `setTimerInList` (start, pause or abort one task's timer; starting pauses every other running one) and `settleTimer` (the task as archived: timer stopped, no `active`, `trackedSeconds` always present))
- `functions/snooze.js` (pure: `normalizeSnooze`, `snoozeDate` and `isSnoozed`; the planner, the slot checks and the fingerprint all read the snooze date through it)
- `functions/duplicates.js` (`findDuplicateTasks`: which queued tasks are copies of an earlier one)
- `functions/projects.js` (pure: project name and order-number validation, `applyProjectFields` for a task's project membership, project create, rename and `setProjectLocation` helpers, removing a project from its tasks)
- `functions/projectTemplates.js` (pure: `buildTemplateSteps` (a project's queued tasks as steps, by order number, the unordered last, at most `MAX_TEMPLATE_STEPS` 100), `stepFromTask`, `addTemplate`, `renameTemplate`, `templateChanges` and `startFromTemplate`, which adds the project and a new task per step through `mergeTaskChanges`)
- `functions/csvExport.js` (pure: `parseCsvRequest` (`{from, to}` local dates), `buildCompletedCsv` (the completed-work CSV: a byte order mark, CRLF line ends, text cells starting with `=`, `+`, `-`, `@`, tab or return given a leading apostrophe against spreadsheet formulas) and `CSV_MAX_ROWS` 10000)
- `functions/location.js` (pure: `taskCoordinates`, `{taskId: {latitude, longitude}}` for the tasks whose effective location has coordinates, and `normalizeLocation`, a place `{name, latitude?, longitude?}`: `name` one line of 1..`MAX_LOCATION_NAME_LENGTH` 200 characters, the coordinates both or neither, latitude -90..90 and longitude -180..180, and a name when there are coordinates; null for none, undefined for an unusable value; and `effectiveLocation(task, project, client)`, the first location that is set of the three, `{location, source, from}` or null)
- `functions/clients.js` (pure: `normalizeClientFields` (name, phone, email, optional hourly rate, `useWhatsApp` and `location`), `sortClients`, `addClient`, `updateClient`, `removeClientFromProjects`, `setProjectClient`, `clientLines`, the lines a job sheet prints (name, location text, phone, email), `clientHourlyRate`, the rate a sheet bills a client's work at: the client's own, 0 included, else the global one)
- `functions/recurrence.js` (pure date arithmetic for the next occurrence of a recurring task)
- `functions/due.js` (pure overdue check)
- `functions/completed.js` (pure limit clamping, serialising of archive documents and the weekly/priority/tag/project/job summary with the streaks, and `summarizeProjectHours`, the all-time hours of each project per Monday-to-Sunday week)
- `functions/completedEdit.js` (pure: `isArchiveId` and `applyCompletedEdit`, the validated corrections to an archived completion)
- `functions/reopen.js` (pure: `reopenTask`, a completed task's archive row turned back into a queued task, and `historyBefore`)
- `functions/jobNumber.js` (pure: `normalizeJobNumber`, `lastIssued` (the counter document's value, 0 when unusable) and `formatJobNumber`)
- `functions/addRequests.js` (pure: `normalizeRequestId`, `requestIdsOf`, `isRepeatedRequest` and `recordRequest`, the ids that make a repeated add, completion, reopen or undo a no-op)
- `functions/clientTime.js` (pure: `resolveActionTime`, the instant to book for a change made on the device, and `normalizeArchiveId`)
- `functions/backfill.js` (pure: `planBackfill`, which numbers the tasks and completed tasks that have no job number, oldest first, on from the counter) with `functions/scripts/backfillJobNumbers.js` (`npm run backfill-job-numbers`, a one-off that applies it to the taskhub-next database: a dry run unless given `--apply`, moving the counter first, safe to run again)
- `functions/addressMigration.js` (pure: `planAddressMigration`, which gives a client's old `address` to its location text when it has no location and removes the key) with `functions/scripts/migrateClientAddresses.js` (`npm run migrate-client-addresses`, a one-off, a dry run unless given `--apply`, safe to run again; the address field has gone from the form and the server, so run it once to keep stored addresses)
- `functions/descriptionMigration.js` (pure: `planDescriptionMigration`, which moves a stored text `comments` to `description` on queued tasks, completed tasks and project template steps and removes the old key, keeping a different description a document already has and reporting the dropped text; a `comments` that is not text is never touched) with `functions/scripts/migrateCommentsToDescription.js` (`npm run migrate-comments-to-description`, a one-off, a dry run unless given `--apply`, safe to run again; run it once after the deploy that renamed the field)
- `functions/photos.js` (pure: `normalizePhoto` (base64 JPEG, signature checked, at most `MAX_PHOTO_BYTES` = 300 KB decoded), `canAddPhoto` (at most `MAX_PHOTOS` = 3 per completed task), `serializePhoto`, `sortPhotos`)
- `functions/export.js` (pure: `buildExport`, the data export document)
- `functions/jobsheet.js` (`parseJobSheetRequest`, `buildJobSheet`, the pure content of a job sheet whose project figures come from `summarizeProjectHours`, `pdfText`, text cleaned for the PDF font: emoji and control characters removed, and the photo helpers `sheetArchiveIds`, `gatherPhotos` (reads entries' photos through injected `fetchChunk` and `countChunk` functions, 30 entries per query, only counting once `JOB_SHEET_MAX_PHOTOS` = 60 is reached) and `withPhotos`)
- `functions/jobsheetPdf.js` (`renderJobSheetPdf`: draws a job sheet with `pdfkit` on A4 in DejaVu Sans, from the `dejavu-fonts-ttf` package, because the built-in PDF fonts cannot print macrons; page numbers on every page; each entry's photos two to a row, scaled to fit half the page width and 190 pt, the JPEG embedded as is, a picture the library cannot read skipped)
- `functions/weather.js` (pure: Open-Meteo URL for a location and time zone (current weather plus a `WEATHER_DAYS`-day daily forecast), `weatherKey` (coarse WET/DRY/OTHER condition), `parseForecast` (the daily forecast as per-day records with a `rainy` flag: the day's dominant condition is wet or at least 1 mm is forecast, and the chance of rain is at least 40% (a day with no chance figure is judged on those signs alone); or at least 3 mm is forecast whatever the chance) and `forecastKey` (the weather summary used in the run fingerprint), `isWeatherSensitive` (a task tagged Outdoor or Garden, ignoring case) and `weatherWindow` (the last local date of the forecast window and the rainy dates in it, for the weather rule in `schedule.js`))
- `functions/fingerprint.js` (pure: `computeFingerprint`, `normalizeBusy`, `hasEndedSlot` and `shouldSkipRun`, the quota guard described under the scheduling engine)
- `functions/prompts.js` (pure: `buildTaskPrompt`, the prompt that parses free text into tasks, which lists the existing project names (the model is told it cannot put a task in a project) and, with `proposals`, also asks conservatively for a project suggestion, and `buildTagPrompt`, the prompt that suggests tags for a title)
- `functions/proposal.js` (pure: `checkProposal` (`{proposal}` or `{reason}`, the reason being logged when a free-text add gets no suggestion) and `normalizeProposal` (its proposal or null), the model's suggested project checked: a name and `MIN_STEPS` 3 to `MAX_STEPS` 12 ordered steps, each `{title, priority, estimatedMinutes, tags, description?}` validated like a manual entry (`description` as `normalizeDescription` does, the key absent when there is none); `namesProject`, `normalizeStep`; `proposalChanges`, the steps as new-task changes with `projectOrder` 1..n; `acceptProposalInList`, which re-checks an accepted suggestion against the stored projects and adds the project and its tasks; `applyChanges`, the checked changes list of a declined one, at most `MAX_APPLY_CHANGES` 100)
- `functions/templates.js` (pure: `buildTemplates`, completed tasks as one template per distinct title, with the job's history)
- `functions/history.js` (pure: a job's history, `completedCount` and `recentSeconds`: `recordCompletion`, `averageMinutes` (the rolling average rounded to the nearest 5 minutes, `roundToFive`), `normalizeHistory`)
- `functions/settings.js` (pure: defaults, field validation (including the daily window's cross-check), `mergeSettings`, `applySettingsUpdate`, `dayWindowMinutes` and the `isRunDue` check and `claimRun` for the auto-run schedule)
- `functions/store.js` (`makeTaskStore(db)`: `updateTaskList` (optionally reading `projects` and the job counter in the same transaction, and storing a larger counter with the tasks) and `getTasks` over the `tasks/{id}` collection, plus the pure `diffTasks`; `makeProjectStore(db)`: `getProjects`, `createProject`, `renameProject`, `setProjectLocation` and `deleteProject` (which also removes the project from its member tasks, in one transaction) over `projects/{id}`; `makeClientStore(db)`: `getClients`, `createClient`, `updateClient` and `deleteClient` (which also takes the client off its projects, in one transaction) over `clients/{id}`, `setProjectClient` on the project store; `makeShoppingStore(db)`: `getItems`, `addItem` and `removeItem` (each write a read-modify-write transaction) over the one document `settings/shoppingList`; `makeTemplateStore(db)`: `getTemplates`, `saveTemplate` (reads the project's tasks and the templates in one transaction), `renameTemplate` and `deleteTemplate` over `project_templates/{id}`; `makeSettingsStore(db)`: `getSettings`, `updateSettings`, the transactional `claimAutoRun`, `setRunFingerprint`, `addDeviceToken`, `removeDeviceTokens` and `claimReminderWindow` (one transaction: the window since `lastReminderAt`, then records now) over `settings/app`)
- `functions/time.js` (local date, minutes-of-day, UTC offset, wall-clock instant, ISO-with-offset, day-start and formatting helpers; every one takes the IANA time zone as its first argument and throws without one).

## Tests

- Tests are `node --test` specs in `functions/test/` (`npm test`), covering every module except the endpoints and engine in `index.js`; `pwa.test.js` checks the manifest, icon files, page links, Hosting headers and the service worker's cache rules; the frontend's pure helpers (tab names, sign-in fallback, snooze dates and list order, formatters, due-day count, schedule text, geocoding mapping, settings payload, project fields, label, task counts, delete prompt, stats text, export text, job sheet file names, Reorder drop targets and the dark-mode choice) sit between `// <pure-helpers>` and `// </pure-helpers>` in `public/index.html`, and `frontend.test.js` extracts that block and runs it, so keep it free of DOM and network access; `calendar.js` and `store.js` are tested against fake clients.
