# Frontend: Queue page

The Queue page's layout, Active task box, search, sort, Multi-Select, reordering, and the Tags and Projects sections.

## Queue page layout and the Active task

- The Queue page is one card (`#queueCard`), with no heading or collapsing, running in this order: the add section (`.add-section`, called the add card in the other docs: its one text field both adds a task and searches the Queue, frontend-tasks.md), the offline notes, then the Active task box (`#activeTaskBox`, hidden when there is none): the task whose timer is running, else the one marked `active` (`activeTaskOf`; it stays there when paused until a timer is started on another task), shown as an ordinary task row with its tracked time ("Tracked 7:05", ticking while the timer runs), the whole box shaded green while the timer runs and amber while it is paused, with a warning under the box once the timer has run `timerWarnHours` without a pause (`longTimerWarning`: "This timer has been running for 7:12 without a pause", with Pause, keep all and Pause, keep 6:00:00, which sends `capSeconds`; its buttons are not part of the card's gestures; checked every second by the ticker) (`timer-running`, `timer-paused`; `--timer-run-bg`, `--timer-pause-bg`), whatever the search, filters and sort, and left out of the list below. Under it the card runs: the Project field, the Tags section, the Sort by row, the Select row (with `#batchStatus` under it), then the list.

## Search and sort

- The Queue has no search box of its own: it is searched with the add card's text field (`#taskInput`, placeholder "Add or search tasks, #job, @client") and its Clear button (`#clearSearchBtn`, between the field and Add, shown only while the field has text, emptying the field and showing the whole list again). The list is redrawn on every keystroke, and adding a task, or a held add, empties the field and so ends the search; tapping a past task copies its title into the field and so narrows the list to the tasks already queued under it. A task shows when every word typed appears in its title, ignoring case, and a word of the form `#123` matches only the task whose job number is 123 and a word of the form `@smith` must appear in the name of the client of the task's project (`matchesSearch`, `jobNumberWords`, `projectClientNameById`: leading zeros ignored, a bare `#` or `@` ignored, ignoring case and part of a word is enough, every `@` word must be in that name so "Smith Ltd" is `@smith @ltd`, a task with no project or client never matches one; tags and projects are not searched, they have their own filters; the add card's past-task list reads such a word as text; the placeholder says `#job` and `@client` can be used), and it combines with the tag and project filters. At the bottom of the filter section, below the Tags section and above the list, a Sort by select (Priority, Date added, Due date, Scheduled date, Task number, Name; Scheduled date at the start) and an Ascending/Descending button (`sortTasks`; per page load, not saved) order the list. Each sorts by that field alone, with ties in the tasks' rank (`order`): ascending is the queue's own order for Task number, A to Z by title (ignoring case, numbers in numeric order, so same-named tasks sit together), High priority first, oldest added first (a task without `addedAt` counts as the oldest), earliest due or scheduled first (a task with none counts as the latest, so descending puts it first), and a scheduled slot sorts by its local date and time, an all-day one at the start of its day.

## Multi-Select

- A Select tasks button (`#selectModeBtn`, `setSelectMode`), in a row of its own under the sort row, toggles Multi-Select (`selectMode`): queued cards, never the Active task, lose their swipe, double-tap and hold, and a tap acts at once, with no wait for a second tap, toggling one in `selectedIds` (`toggleSelected`: the `selected` class, a blue outline and tint with no tick box, so a card keeps its normal layout and line count, `aria-checked` for assistive tools; `pruneSelection` drops tasks that left the list; the selection survives search, tag and project changes, and `batchCountText` says how many selected tasks they hide). A sticky bar (`#batchBar`) shows the count with All shown and None, and Complete, Delete, Snooze, To top, Project and Due date, which act on every selected task, shown or not. Complete and Delete (`batchRemove`, after `batchRemovePrompt`) call `removeTask` for each task in queue order with `noUndo` (no Undo footnote: the server keeps one undo step) and leave a task whose call failed selected (one that fails on the connection is held and sent in order, `offline.md`, so it counts as done); the others post `batchBody` to `batchUpdateTasks` (`batchSend`; `#batchModal` takes the snooze day or due date; Project opens the picker modal at once (`pickBatchProject`; frontend-shell.md), titled "Add 3 tasks to a project", with None first, and the pick is sent as soon as it is made: a project as `projectId`, None as `projectId: null` (takes the tasks out of their project and drops their order numbers; reassigning to None undoes a wrong assignment), the Add row's name as `newProject`; To top needs no dialog). A successful To top, Snooze, Due date or Project keeps Multi-Select on and the selection as it was (`pruneSelection` drops any task that left the list), ready for another action, and reports in `#batchStatus`; a successful Complete or Delete leaves Multi-Select; a failed batch alerts and keeps the selection. To top, Snooze, Due date and Project (an existing project or None) are held with no connection, or behind changes already waiting, and sent in order (`offline-edits.md`); a new project needs a connection.

## Reorder

- A queued card held for `LONG_PRESS_MS` 500 lifts to be dragged, for touch and mouse alike: `onTaskRowDown` times the hold and `startReorderPress` lifts the card (`reorderDrag`, which exists only while a card is lifted). The Active task, and queued cards while Multi-Select is on, never lift. A drag that starts sideways before the hold is still the swipe and a finger that moves up or down before it still scrolls (`pressMoved`, `cancelPress`); releasing a lifted card without moving does nothing (`pressFired`), and a release before the hold is a tap. Cards can be reordered only while the list is in the queue's own order, Sort by Task number ascending (`reorderAllowed`); under any other sort a hold does not lift but shows a toast (`showToast`, frontend-shell.md) saying `REORDER_HINT_TEXT`, "Sort by Task number, ascending, to reorder cards.", which goes again at the next sort change or when Multi-Select starts (`hideToast`) and moves nothing on the page. The lifted card follows the pointer and the cards it passes slide aside (`paintReorder`, `dragTargetIndex`), the page scrolls itself near the bottom edge and just under the pinned header, and Escape or a cancelled touch drops the card where it was. Releasing sends the move: the card takes the task number of the card it lands on (`reorderQueueNumber`, what typing that number in the edit modal does, so it works on a list narrowed by search or filters, hidden tasks keeping their relative places and the Active task's number leaving a gap), shown at once (`moveToQueueNumberInList`, a copy of the server's `moveToQueueNumber`, kept equal by a test) and saved through `updateTaskDirect` with `queueNumber`, one call at a time in order (`reorderTask`, `reorderChain`); the server's list replaces the page's once none is waiting, and a failed save alerts and reads the list again with `getTasks`. The Undo footnote offers "Moved “Fix gate” to #3" (`reorderMessage`) and Undo moves the task back to its old number without a footnote of its own. A move never reschedules: the task number decides the planner's order only when Schedule tasks by is Task number, otherwise it only breaks ties.

## Tags, projects and project templates

- Under the search box sit the Project field and then the Tags section; the status line under the field (`#projectsStatus`) takes no space while it is empty, so every row sits the standard 10 to 12 px from the next. The Tags section is collapsible, collapsed by default and headed by a full-width bordered, padded row so the whole row is the tap target; its heading shows the active filter ("· Outdoor") so it stays visible when the section is collapsed. It holds the tag chips, with an All chip, in alphabetical order ignoring case (`sortedTags`); a tap on a tag chip toggles it in the filter (`selectedTagFilters`, `toggleTagFilter`), several tags match with OR (a task shows when it carries any of them), All clears every chosen tag, a tag no task carries any more is dropped (`pruneTagFilter`), and the heading lists the chosen tags ("· Outdoor, Garden", `tagFilterLabel`). The Project field (`#queueProjectField`, a `.picker-field` button in `#projectsSection`, with the label "Project" at its left on the same line, `#queueProjectLabel`; disabled until `getProjects` has answered) shows "All" or the chosen project's name and opens the picker modal (`openQueueProjectPicker`, kind `queue`; frontend-shell.md): a search field with an Add button beside it, an All row first (the number of queued tasks at its right) and one row per project, every project with no cap (alphabetical, as the server sorts them, `sortProjects`), each with its queued task count and its client's name at the right ("2 · Smith Ltd", "0" with no tasks and no client; `pickerRows`), the chosen row marked. What is typed narrows the rows live (`filterProjects`: every word must appear in the project's name or its client's name, ignoring case, `projectSearchText`; "No projects match the search." when none do, and the All row shows only while the search is blank). A row tap chooses the project (`selectQueueProject`, `setProjectFilter`) and closes the modal. Add (the button, or Enter when nothing matches the typed text) creates the project (`addProject`: `CREATE` through `saveProject`, whose reply's `project` is the one chosen), chooses it, and leaves the modal open with the search emptied, the whole list showing and the new row marked; the result (`Added "Deck".`, or the server's reason, such as a taken name, with the typed text kept) shows in the modal's status line (`#pickerStatus`) as well as `#projectsStatus` on the page. The chosen project stays chosen whatever is typed. The chosen project's actions are a collapsible Manage section of the modal (`#pickerManage`, below the list and its status line, above Cancel; the heading "Manage · Kitchen reno" shows the project's name; collapsed on every open and when Add chooses a new project; shown only while a project is marked in the modal, never for All, and only while this modal is the one in front: `managedProject` finds the marked project (the modal's `current`, not the Queue filter), `renderPickerManage` shows the section and `renderManage` draws it for that project, `managedProjectId` being the project the Location and Link rows and the address search act on; `renderPicker` redraws it with the rows, so a rename or a client change shows at once, rewriting a block's markup only when it changed (`setManageHtml`) so a redraw keeps focus): the Rename and Delete buttons of the chosen project (Rename is a prompt, Delete a confirmation that says its tasks stay on the list, and a successful Delete closes the modal), under them its Client button (`#projectClient`, `clientPickerHtml`: the client's name, "No client", or "New client" while the form below is open; shown even with no clients yet), which opens the client picker (`pickProjectClient`; frontend-shell.md; it opens over the modal, which comes back as it was when the picker closes) with a "No client" row first: a stored client or No client is posted at once as `SET_CLIENT` (`setClientBody`), choosing the client already set sends nothing; the picker's Add row for a typed name saves nothing but opens the whole client form, its Name filled with the typed text, (the Clients form block, prefix `projectClient`, in fixed markup `#projectNewClient` beneath the actions so a redraw never wipes typed text; frontend-settings.md) with its own Add and Cancel: Add (`addClientToProject`) sends `SET_CLIENT` with `newClient`, a missing name or a bad email, link or rate being a warning alert that sends nothing (`newClientWarning`), and the reply's `clients` replace `allClients` (`takeClients`); the form closes and empties on a successful Add, Cancel, another Client choice, another project chosen, or the project going, and stays as typed when the server refuses (a taken name shows in the status line); under that its Location row (fixed markup, `#projectLocation`, hidden with no project chosen; `renderProjectLocation` rewrites the box only when `projectLocationKey` (the project and its own location) changes, so a redraw never wipes typed text): the field is a type-ahead through `makePlacesAutocomplete` (`makePlaceSearch` with a Find on map button without a Places key), picking a suggestion saves it as the project's own location at once as `SET_LOCATION` (to the project chosen when it was tapped), and Clear (shown only with an own location) sends null; the note under it says "📍 Map position set." for an own location or "From client: Smith Ltd · 12 Beach Road" while inheriting (`projectLocationView`, using the page's copy of `effectiveLocation`, which a test keeps equal to the server's); then its Link row (fixed markup, `#projectUrl`, hidden with no project chosen; `renderProjectUrl` rewrites the box only when `projectUrlKey` (the project and its own link) changes): a text box with Save link (or Enter: `setProjectUrl` posts `SET_URL` with `parseUrlText`'s result, so an empty box removes the project's own link; a bad link is a warning alert (`INVALID_URL`) and nothing is sent) and Clear (shown only with an own link); the note says "🔗 Link set." for an own link, "From client: Smith Ltd · https://example.com/job" while inheriting or "No link yet. Add one to set it." (`projectUrlView`); then the Save as template button row (`#projectTemplateAction`: a button that asks for the name, defaulting to the project's; `saveAsTemplate`). Below Manage, above Cancel, is a second collapsible section, Start from template (`#pickerTemplates`; collapsed on every open, shown with All chosen as well as with a project, and only while this modal is the one in front, `renderPickerTemplates`, redrawn with the rows). It holds the template block (`#templateBlock`: a select of the templates with their step counts (`templateStepsText`), a name field for the new project (empty means the template's name, numbered when taken, `defaultProjectName`), Start, Rename template and Delete template (a confirmation, `deleteTemplatePrompt`), or "No templates yet. Choose a project, open Manage and tap Save as template." while there are none; `loadProjectTemplates` after sign-in through `getProjectTemplates`, `allTemplates`, every change through `updateProjectTemplate`). Start replaces the task and project lists from the response, reports `startedText` on the page's status line (`#projectsStatus`) and closes the modal; a failed Start leaves it open with the reason in the modal's status line. `getProjects` loads after sign-in, every change goes through `updateProject`, and a delete replaces the task list from the response. Tags and a project can both be chosen and then the list shows the tasks matching any chosen tag and the project (`filterTasks`, which also takes the search text); a chosen project that no longer exists is dropped, and an empty result says no tasks match the search and filters.
