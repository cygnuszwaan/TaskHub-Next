# Frontend: Queue page

The Queue page's layout, Active task box, search, sort, Multi-Select, Reorder, and the Tags and Projects sections.

## Queue page layout and the Active task

- The Queue page runs in this order: the add card (no heading; "Add New Task" is the empty text field's placeholder), then the Queue card, which has no heading or collapsing of its own. The Queue card's very first element is the Active task box (`#activeTaskBox`, hidden when there is none): the task whose timer is running, else the one marked `active` (`activeTaskOf`; it stays there when paused until a timer is started on another task), shown as an ordinary task row with its tracked time ("Tracked 7:05", ticking while the timer runs), the whole box shaded green while the timer runs and amber while it is paused, with a warning under the card once the timer has run `timerWarnHours` without a pause (`longTimerWarning`: "This timer has been running for 7:12 without a pause", with Pause, keep all and Pause, keep 6:00:00, which sends `capSeconds`; its buttons are not part of the card's gestures; checked every second by the ticker) (`timer-running`, `timer-paused`; `--timer-run-bg`, `--timer-pause-bg`), whatever the search, filters and sort, and left out of the list below.

## Search and sort

- The Queue starts with a live search box (`#taskSearch`) with a Clear button beside it that shows only while the box has text (phones show no clear control of their own, so the browser's is hidden): the list is redrawn on every keystroke, and a task shows when every word typed appears in its title, ignoring case, and a word of the form `#123` matches only the task whose job number is 123 (`matchesSearch`, `jobNumberWords`: leading zeros ignored, a bare `#` ignored; tags and projects are not searched, they have their own filters; the add card's template search reads such a word as text), and it combines with the tag and project filters. Under the search box, a Sort by select (Priority, Date added, Due date, Scheduled date, Task number, Name; Scheduled date at the start) and an Ascending/Descending button (`sortTasks`; per page load, not saved) order the list. Each sorts by that field alone, with ties in the tasks' rank (`order`): ascending is the queue's own order for Task number, A to Z by title (ignoring case, numbers in numeric order, so same-named tasks sit together), High priority first, oldest added first (a task without `addedAt` counts as the oldest), earliest due or scheduled first (a task with none counts as the latest, so descending puts it first), and a scheduled slot sorts by its local date and time, an all-day one at the start of its day.

## Multi-Select

- A Select tasks button (`#selectModeBtn`, `setSelectMode`), sharing one row under the sort row with a Reorder button (`#reorderModeBtn`, below), toggles Multi-Select (`selectMode`): queued cards, never the Active task, lose their swipe and long-press and a tap toggles one in `selectedIds` (`toggleSelected`: a ☐/☑ mark and the `selected` class; `pruneSelection` drops tasks that left the list; the selection survives search, tag and project changes, and `batchCountText` says how many selected tasks they hide). A sticky bar (`#batchBar`) shows the count with All shown and None, and Complete, Delete, Snooze, To top, Project and Due date, which act on every selected task, shown or not. Complete and Delete (`batchRemove`, after `batchRemovePrompt`) call `removeTask` for each task in queue order with `noUndo` (no Undo footnote: the server keeps one undo step) and leave a task whose call failed selected (one that fails on the connection is held and sent in order, `offline.md`, so it counts as done); the others post `batchBody` to `batchUpdateTasks` (`batchSend`; `#batchModal` takes the snooze day or due date; Project opens the picker modal at once (`pickBatchProject`; frontend-shell.md), titled "Add 3 tasks to a project", with None first, and the pick is sent as soon as it is made: a project as `projectId`, None as `projectId: null` (takes the tasks out of their project and drops their order numbers; reassigning to None undoes a wrong assignment), the Add row's name as `newProject`; To top needs no dialog). A successful batch leaves Multi-Select and reports in `#batchStatus`; a failed one alerts and keeps the selection. To top, Snooze, Due date and Project (an existing project or None) are held with no connection, or behind changes already waiting, and sent in order (`offline-edits.md`); a new project needs a connection.

## Reorder

- The Reorder button (`setReorderMode`, `reorderMode`; starting it ends Multi-Select and the other way round) forces Sort by to Task number, Ascending, disables the two sort controls and keeps the earlier choice (`sortBeforeReorder`) to put back when the mode ends; a hint line (`#reorderHint`) explains the gesture. Queued cards, never the Active task, lose swipe, long press and tap, show a ↕ mark and are dragged instead: a touch must rest on a card `REORDER_HOLD_MS` 250 before it lifts (moving sooner scrolls the list as usual; once lifted, a non-passive `touchmove` listener holds the page still), a mouse drags after moving `REORDER_MOUSE_PX` 4. The lifted card follows the pointer and the cards it passes slide aside (`paintReorder`, `dragTargetIndex`), the page scrolls itself near the bottom edge and just under the pinned header, and Escape or a cancelled touch drops the card where it was. Releasing sends the move: the card takes the task number of the card it lands on (`reorderQueueNumber`, what typing that number in the edit modal does, so it works on a list narrowed by search or filters, hidden tasks keeping their relative places and the Active task's number leaving a gap), shown at once (`moveToQueueNumberInList`, a copy of the server's `moveToQueueNumber`, kept equal by a test) and saved through `updateTaskDirect` with `queueNumber`, one call at a time in order (`reorderTask`, `reorderChain`); the server's list replaces the page's once none is waiting, and a failed save alerts and reads the list again with `getTasks`. The Undo footnote offers "Moved “Fix gate” to #3" (`reorderMessage`) and Undo moves the task back to its old number without a footnote of its own. A move never reschedules: the task number decides the planner's order only when Schedule tasks by is Task number, otherwise it only breaks ties.

## Tags, projects and project templates

- Below it, above the list, sit two collapsible sections, Tags and then Projects, both collapsed by default and each headed by a full-width bordered, padded row so the whole row is the tap target; each heading shows the active filter ("· Outdoor", "· Kitchen reno") so it stays visible when the section is collapsed. The Tags section holds the tag chips, with an All chip, in alphabetical order ignoring case (`sortedTags`); a tap on a tag chip toggles it in the filter (`selectedTagFilters`, `toggleTagFilter`), several tags match with OR (a task shows when it carries any of them), All clears every chosen tag, a tag no task carries any more is dropped (`pruneTagFilter`), and the heading lists the chosen tags ("· Outdoor, Garden", `tagFilterLabel`). The Projects section opens with the project field (`#newProjectName`, placeholder "Search projects or clients, or type a new project name") and its Add button, then a list (`#projectFilterBar`, rows `.project-item`): an All row and one row per project (alphabetical, as the server sorts them, `sortProjects`) ("📁 Kitchen reno (2)", the count being its tasks, with the project's client name in muted text at the row's right when it has one), the chosen row highlighted. What is typed in the project field narrows the rows live (`filterProjects`: every word must appear in the project's name or its client's name, ignoring case, `projectSearchText`; "No projects match the search." when none do); the chosen project stays chosen, and its actions stay, even when the search hides its row, and a successful Add empties the field so the whole list shows again. Below the list sit the Rename and Delete buttons of the chosen project (Rename is a prompt, Delete a confirmation that says its tasks stay on the list), under them its Client button (`#projectClient`, `clientPickerHtml`: the client's name, "No client", or "New client" while the form below is open; shown even with no clients yet), which opens the client picker (`pickProjectClient`; frontend-shell.md) with a "No client" row first: a stored client or No client is posted at once as `SET_CLIENT` (`setClientBody`), choosing the client already set sends nothing; the picker's Add row for a typed name saves nothing but opens the whole client form, its Name filled with the typed text, (the Clients form block, prefix `projectClient`, in fixed markup `#projectNewClient` beneath the actions so a redraw never wipes typed text; frontend-settings.md) with its own Add and Cancel: Add (`addClientToProject`) sends `SET_CLIENT` with `newClient`, a missing name or a bad email, link or rate being a warning alert that sends nothing (`newClientWarning`), and the reply's `clients` replace `allClients` (`takeClients`); the form closes and empties on a successful Add, Cancel, another Client choice, another project chosen, or the project going, and stays as typed when the server refuses (a taken name shows in the status line); under that its Location row (fixed markup, `#projectLocation`, hidden with no project chosen; `renderProjectLocation` rewrites the box only when `projectLocationKey` (the project and its own location) changes, so a redraw never wipes typed text): the field is a type-ahead through `makePlacesAutocomplete` (`makePlaceSearch` with a Find on map button without a Places key), picking a suggestion saves it as the project's own location at once as `SET_LOCATION` (to the project chosen when it was tapped), and Clear (shown only with an own location) sends null; the note under it says "📍 Map position set." for an own location or "From client: Smith Ltd · 12 Beach Road" while inheriting (`projectLocationView`, using the page's copy of `effectiveLocation`, which a test keeps equal to the server's); then its Link row (fixed markup, `#projectUrl`, hidden with no project chosen; `renderProjectUrl` rewrites the box only when `projectUrlKey` (the project and its own link) changes): a text box with Save link (or Enter: `setProjectUrl` posts `SET_URL` with `parseUrlText`'s result, so an empty box removes the project's own link; a bad link is a warning alert (`INVALID_URL`) and nothing is sent) and Clear (shown only with an own link); the note says "🔗 Link set." for an own link, "From client: Smith Ltd · https://example.com/job" while inheriting or "No link yet. Add one to set it." (`projectUrlView`); then the Save as template button row (`#projectTemplateAction`); then a Start from template block (`#templateBlock`: a select of the templates with their step counts (`templateStepsText`), a name field for the new project (empty means the template's name, numbered when taken, `defaultProjectName`), Start, Rename template and Delete template (a confirmation, `deleteTemplatePrompt`); `loadProjectTemplates` after sign-in through `getProjectTemplates`, `allTemplates`, every change through `updateProjectTemplate`; Start replaces the task and project lists from the response and reports `startedText`), and the chosen project's Save as template button (a prompt for the name, defaulting to the project's) sits under its Location row; `getProjects` loads after sign-in, every change goes through `updateProject`, and a delete replaces the task list from the response. Tags and a project can both be chosen and then the list shows the tasks matching any chosen tag and the project (`filterTasks`, which also takes the search text); a chosen project that no longer exists is dropped, and an empty result says no tasks match the search and filters.
