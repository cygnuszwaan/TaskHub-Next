# Frontend: Materials page

The Materials page's cards: Task materials and the Miscellaneous shopping list.

## Materials page cards

- The Materials page is three cards, one under the other, each a collapsible `<details class="card settings-card">` (as on the Settings page: the title with a turning chevron, no `open` attribute, so all three are collapsed on every load and the open state is not remembered): "Task materials" (`#taskMaterialsSection`): every unchecked material of every task, grouped under its task's title (tap to open the task), with the count in its tab ("Materials (3)"); its footnote (`#materialsStatus`) is its own. "Groceries" (`#grocerySection`, footnote `#groceryStatus`) and "Miscellaneous" (`#shoppingSection`, footnote `#shoppingStatus`): two plain lists of the same kind, described below as Miscellaneous (the Groceries card is the same card with its own add field `#groceryInput`, list `#groceryList`, saved-copy note `#groceryOfflineNote` and Retry button, reading `getGroceryList` and changing through `updateGroceryList`; its changes are SHOPPING_ADD and SHOPPING_REMOVE actions with `list: "grocery"`). One implementation serves both: every shopping function takes the list (`"shopping"` for Miscellaneous, the default, or `"grocery"`), each list's state is `shoppingState[list]` (`items`, `loaded`, `server`, `syncAt`, `savedAt`, `pending`, `chain`, `realIds`) and its elements `SHOPPING_ELEMENTS[list]`, so the two never share a pending change, saved copy, footnote or Undo (a tick's footnote key is `shopping:<id>` or `grocery:<id>`). Checking a material takes it off the card at once and offers Undo in the footnote ("Checked off “Nails”", `checkOffMessage`; Undo unticks it, an alert saying so if its task has gone) (`checkMaterial`: `withTaskMaterialChecked` on the page's list, then the save through `updateTaskDirect` of the task's whole list with this one box set (`withMaterialChecked`) runs in the background, one after another on `materialsChain`; the server's list replaces the page's only when none is waiting, and a failed save puts the box back with a message under the card). A tick made while changes are waiting in the action queue, or whose save fails on the connection (`isNetworkError`), is kept instead by `holdMaterialCheck` as an EDIT of the task's `materials` and shown at once: the list is the queue's view of the task with this box set (`shownTasks`), every item with an id of its own (`withMaterialIds`), merged into the queue's last action when that is a waiting materials-only EDIT of the same task and not on its way (`coalesceMaterialsEdit`), so ticking a list takes one place in the queue; the task's group on the card shows a "⏳ Waiting to send" chip (`waitingIds`), Undo works as online, and a refusal to keep it (a full queue, unusable storage) puts the box back with the reason under the card. A tick or an add made while changes are waiting, or whose save fails on the connection, is kept in the action queue and shown at once (`offline-edits.md`). Miscellaneous is a plain shopping list that belongs to no task and does not count in the tab's number: an add field with an Add button (Enter adds too; `shoppingItemText` trims the text, a blank one adds nothing) and the items in the order added, each with a checkbox that takes it off the list (`checkShoppingItem`); `loadShoppingList` reads `getShoppingList` after sign-in (with no connection it shows the list's saved copy under a note, see `offline.md`) and every change goes through `updateShoppingList`. An add or a tick shows at once (`shoppingWithAdded`, `shoppingWithout`, on the same rules as the server: a text already there ignoring case is not added again, at most `MAX_SHOPPING_ITEMS` 100) and `queueShopping` saves it in the background in order (`shoppingState[list].chain`); a new item carries a temporary id ("pending-" and its request id) until the server answers with its own (`shoppingState[list].realIds`, so an item ticked before its add came back is removed under the real id); a save that fails for any other reason takes its change back (`shoppingWithRestored` for a removal, the typed text returned to an empty field for an add), clears the footnote it raised and says so under the section; ticking an item also offers Undo in the footnote, which adds the item again at the end of the list (`addShoppingText`); once nothing is waiting the server's list replaces the page's. A list that has not loaded shows nothing rather than "Nothing on the list.", and an add then retries the load instead.
