# Frontend: the Project modal

The Queue's Project field and the picker modal it opens (`#pickerModal`, kind `queue`): the rows, Add, Manage and Start from template. Every single-task Project field opens the same modal (below). The modal's generic mechanics (layers, search, keyboard, kinds) are in frontend-shell.md; the Queue's layout, tags and search are in frontend-queue.md.

- The Project field (`#queueProjectField`, a `.picker-field` button in `#projectsSection`, with the label "Project" at its left on the same line, `#queueProjectLabel`; disabled until `getProjects` has answered) shows "All" or the chosen project's name and opens the picker modal (`openQueueProjectPicker`, kind `queue`; frontend-shell.md): a search field with an Add button beside it, an All row first (the number of queued tasks at its right) and one row per project, every project with no cap (alphabetical, as the server sorts them, `sortProjects`), each with its queued task count and its client's name at the right ("2 · Smith Ltd", "0" with no tasks and no client; `pickerRows`), the chosen row marked. What is typed narrows the rows live (`filterProjects`: every word must appear in the project's name or its client's name, ignoring case, `projectSearchText`; "No projects match the search." when none do, and the All row shows only while the search is blank). A row tap only marks the project (`pickFromPicker`; the marked row is the modal's `current`, which Manage follows) and keeps the modal open; Save (`savePicker`, after Cancel) applies the mark (`selectQueueProject`, `setProjectFilter`; All if the marked project is gone, `pickerSavedId`) and closes it; Cancel, Back, a tap outside and Escape drop the mark, while Manage changes already sent stay saved. Add (the button, or Enter when nothing matches the typed text) creates the project (`addProject`: `CREATE` through `saveProject`), marks it (the filter changes only on Save) and leaves the modal open with the search emptied, the whole list showing and the new row marked; the modal remembers each project Add made (`created`) and, as it closes, deletes again every one but the one Save applied (`pickerStrayIds`, `discardCreatedProjects`, `DELETE`; it has no tasks yet), so Add then Cancel, or Add then another project and Save, leaves nothing behind, and a failed delete is an alert naming the project (a client made through that project's Manage stays); with no connection Add and the whole Manage section are disabled and the status line says so (`renderPickerOffline`); the result (`Added "Deck".`, or the server's reason, such as a taken name, with the typed text kept) shows in the modal's status line (`#pickerStatus`) as well as `#projectsStatus` on the page. The marked project stays marked whatever is typed. The chosen project's actions are a collapsible Manage section of the modal (`#pickerManage`, below the list and its status line, above Cancel; the heading "Manage · Kitchen reno" shows the project's name; collapsed on every open and when Add marks a new project; shown only while a project is marked, never for All, and only while this modal is the one in front: `managedProject` finds the marked project (the modal's `current`, not the Queue filter), `renderPickerManage` shows the section and `renderManage` draws it for that project, `managedProjectId` being the project the Location and Link rows and the address search act on; `renderPicker` redraws it with the rows, so a rename or a client change shows at once, rewriting a block's markup only when it changed (`setManageHtml`) so a redraw keeps focus): the Rename and Delete buttons of the chosen project (Rename is a prompt, Delete a confirmation that says its tasks stay on the list, and a successful Delete leaves the modal open with the mark back on All), under them its Client button (`#projectClient`, `clientPickerHtml`: the client's name, "No client", or "New client" while the form below is open; shown even with no clients yet), which opens the client picker (`pickProjectClient`; frontend-shell.md; it opens over the modal, which comes back as it was when the picker closes) with a "No client" row first: a stored client or No client is posted at once as `SET_CLIENT` (`setClientBody`), choosing the client already set sends nothing; the picker's Add row for a typed name saves nothing but opens the whole client form, its Name filled with the typed text, (the Clients form block, prefix `projectClient`, in fixed markup `#projectNewClient` beneath the actions so a redraw never wipes typed text; frontend-settings.md) with its own Add and Cancel: Add (`addClientToProject`) sends `SET_CLIENT` with `newClient`, a missing name or a bad email, link or rate being a warning alert that sends nothing (`newClientWarning`), and the reply's `clients` replace `allClients` (`takeClients`); the form closes and empties on a successful Add, Cancel, another Client choice, another project chosen, or the project going, and stays as typed when the server refuses (a taken name shows in the status line); under that its Location row (fixed markup, `#projectLocation`, hidden with no project chosen; `renderProjectLocation` rewrites the box only when `projectLocationKey` (the project and its own location) changes, so a redraw never wipes typed text): the field is a type-ahead through `makePlacesAutocomplete` (`makePlaceSearch` with a Find on map button without a Places key), picking a suggestion saves it as the project's own location at once as `SET_LOCATION` (to the project chosen when it was tapped), and Clear (shown only with an own location) sends null; the note under it says "📍 Map position set." for an own location or "From client: Smith Ltd · 12 Beach Road" while inheriting (`projectLocationView`, using the page's copy of `effectiveLocation`, which a test keeps equal to the server's); then its Link row (fixed markup, `#projectUrl`, hidden with no project chosen; `renderProjectUrl` rewrites the box only when `projectUrlKey` (the project and its own link) changes): a text box with Save link (or Enter: `setProjectUrl` posts `SET_URL` with `parseUrlText`'s result, so an empty box removes the project's own link; a bad link is a warning alert (`INVALID_URL`) and nothing is sent) and Clear (shown only with an own link); the note says "🔗 Link set." for an own link, "From client: Smith Ltd · https://example.com/job" while inheriting or "No link yet. Add one to set it." (`projectUrlView`); then the Save as template button row (`#projectTemplateAction`: a button that asks for the name, defaulting to the project's; `saveAsTemplate`). Below Manage, above Cancel, is a second collapsible section, Start from template (`#pickerTemplates`; collapsed on every open, shown with All chosen as well as with a project, and only while this modal is the one in front, `renderPickerTemplates`, redrawn with the rows). It holds the template block (`#templateBlock`: a select of the templates with their step counts (`templateStepsText`), a name field for the new project (empty means the template's name, numbered when taken, `defaultProjectName`), Start, Rename template and Delete template (a confirmation, `deleteTemplatePrompt`), or "No templates yet. Choose a project, open Manage and tap Save as template." while there are none; `loadProjectTemplates` after sign-in through `getProjectTemplates`, `allTemplates`, every change through `updateProjectTemplate`). Start replaces the task and project lists from the response, reports `startedText` on the page's status line (`#projectsStatus`) and closes the modal; a failed Start leaves it open with the reason in the modal's status line. `getProjects` loads after sign-in, every change goes through `updateProject`, and a delete replaces the task list from the response. Tags and a project can both be chosen and then the list shows the tasks matching any chosen tag and the project (`filterTasks`, which also takes the search text); a chosen project that no longer exists is dropped, and an empty result says no tasks match the search and filters.

- The Project fields of the add card, Edit Task Details and Edit Completed Task (frontend-edit-modal.md) open this modal through `openProjectPicker` with `noneLabel: "None"` (no task count at its right), `title: "Choose a project"`, `onAdd: addProject`, `confirm: true` and `templates: false`: the Start from template section stays hidden (`renderPickerTemplates` reads the state's `templates`, default true). Add and Manage work as above and act at once; Save sets the form's hidden choice through `setProjectField` (None when the marked project is gone, `pickerSavedId`), and the modal deletes every project Add made except the one Save applied. Deleting a project in Manage resets the add card's and queued modal's choice to None (`deleteProject`).
